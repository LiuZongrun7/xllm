02 — What it does

The interesting parts are the rules.

Any interface can render a list of orders. The work is in what happens when two people act at once, when a store is closed, or when someone asks for an order that is not theirs.

03 — The lifecycle

Seven states, one transition table.

04 — Under the hood

One folder per role, one shared core.

The directory tree is the division of work. Each role owns its routes, templates and stylesheet, and shares only the data model, the state machine and the API contract. 

# the tree is the division of work
server/
├── app.py          application factory
├── info/           this site — no db, no session
├── shared/         models · state machine · auth · seed
├── customer/       pages + /api/customer
├── merchant/       pages + /api/merchant
└── rider/          pages + /api/rider

deploy/             systemd unit · nginx config

05 — Design

Three people, three interfaces.

A customer on a phone in the rain, a kitchen manager on a desktop with a queue waiting, and a rider with gloves on. They are not the same person, so they do not get the same screen — each side has its own typography, palette and control sizes.
