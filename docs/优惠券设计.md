# 优惠券设计 · 官方发券 + 付费券包

> 状态：已实现（FR-26）。代码：`server/shared/coupons.py`、`server/customer/routes.py`、
> `server/customer/static/js/customer.js`；表：`coupons` / `user_coupons` /
> `coupon_packages` / `coupon_package_items` / `coupon_purchases`。

---

## 一、为什么这么设计（调研）

美团的券不是"后台建几张券"，而是一套**商品化的营销体系**。官方公开口径把它分成两块：

> "神会员"主要分为**免费神券**和**神会员省钱包**两大板块。前者为免费发放，后者为**付费券包**……
> 推出了 6 张、12 张、20 张不同红包数量规格的省钱包。
> —— [美团"神会员"全面升级（美团官方新闻，2024-07-04）](https://www.meituan.com/zh-HK/news/NN240704052008695?source=relativeNews)

售卖与查看的链路也有公开记录：

> 市民通过美团 App、美团外卖 App 搜索"年末消费季"，或直接在**"神会员"入口**，以 **0.01 元**
> 的价格，即可购买价值 **30 元的 6 张 5 元无门槛券包**。线上购券后，6 张券自动放入账户，点击
> "**我的-红包/卡券-券包**"或"**我的-红包/神券**"即可查看，下单环节直接抵扣。
> —— [1分钱抢购 30 元"省钱包"（北京商报，2024-12-19）](https://www.bbtnews.com.cn/2024/1219/541076.shtml)

归纳出三条可复用的规则：

| 维度 | 做法 |
|---|---|
| 券从哪来 | **平台官方发行**，用户之间不流转 |
| 卖什么 | 付费券包（固定价格 / 固定张数 / 固定有效期），价格低于面额 |
| 在哪卖 / 在哪看 | 首页入口、券包货架；**我的 → 优惠券**；结算页抵扣 |

我们照着这三条做，但按课程项目的规模砍掉了"膨胀""会员卡""免费日领"这些玩法。

## 二、产品形态（本项目）

| 形态 | 规则 |
|---|---|
| **新人限时券** | 顾客注册成功即自动到账，¥15 减（满 ¥40 可用），**48 小时**内有效 |
| **付费券包** | 4 档：¥4.90 / 3 张 ¥5；¥9.90 / 6 张 ¥5；¥6.90 / 3 张 8 折（封顶 ¥12）；¥19.90 / 12 张 ¥5 |
| **我的券** | 可用 / 已用 / 已过期 三个分组，显示到期时间与来源 |
| **结算抵扣** | 一单一张，只抵扣菜品小计，不抵扣配送费 |

不做：免费日领券、券叠加、券码手输、会员卡、膨胀、转赠。

## 三、数据模型

```
coupons                券模板：面额/折扣、门槛、封顶、承担方、有效期
user_coupons           用户手里的券：状态、来源、到期时间、核销订单
coupon_packages        券包商品：价格、面额、张数、有效期、限购、库存、上下架
coupon_package_items   券包内容：(券模板, 张数)
coupon_purchases       购买记录：用户、券包、实付、支付状态
```

订单上有三个快照列：`coupon_id`、`coupon_title`、`coupon_funded_by`。理由和菜品/地址快照一致：
券被改名、停用或涨价以后，历史订单仍然能回看"这一单用了什么券、谁补贴的"。

## 四、钱从哪来（谁承担折扣）

| 角色 | 金额 |
|---|---|
| 顾客实付 | `items + delivery_fee − discount` |
| 商家应收 | `items_amount`（**平台券由平台补，商家不少收钱**） |
| 骑手配送费 | `delivery_fee`（不参与折扣） |
| 平台承担 | `discount_amount` |

平台侧的资金流是两层：

1. **卖券收入**：顾客买券包付的钱（$price$）
2. **核销成本**：每用掉一张券，平台补贴其面额

于是单个券包的盈亏取决于核销率：

| 情形（¥9.90 买 6 张 ¥5，面额 ¥30） | 平台净成本 |
|---|---|
| 6 张全用 | 30 − 9.90 = **20.10** |
| 用 3 张 | 15 − 9.90 = **5.10** |
| 用 1 张 | 5 − 9.90 = **−4.90（净赚）** |
| 一张不用 | **−9.90（净赚）** |

这也解释了美团为什么把核销率当核心指标：**券包收入先落袋，补贴只在核销时发生**。过期未用的
券是平台的净收入，卖券本身就是一门生意，不是纯粹的让利。

## 五、关键规则

| 规则 | 实现 |
|---|---|
| 门槛按菜品小计 | `items_amount >= min_order_amount`，不含配送费 |
| 抵扣上限 | 不超过小计；百分比券再受 `max_discount_amount` 封顶 |
| 一单一张 | `orders` 只存一个券快照 |
| 限购 | 每券包每用户 N 次（`per_user_limit`），购买前计数 |
| 限量 | `total_quantity`，购买时一条条件 `UPDATE` 自增 `sold_count`，卖完即 409 |
| 有效期 | 购买日 + `validity_days`；新人券 48h；**读取时惰性判断过期**，不写定时任务 |
| 核销 | `UPDATE user_coupons SET status='used' WHERE id=? AND user_id=? AND status='unused'`，`rowcount=0` 即 409 |
| 取消退券 | `transition(..., 'cancelled')` 里调用 `release_for_order()`：未过期退回 unused，已过期标 expired |
| 越权 | 券必须属于当前顾客，否则 404（与订单一致，不泄露存在性） |
| 不可退 | 券包是虚拟商品，购买后不退款（页面明示） |

## 六、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/customer/coupons` | 我的券；带 `restaurant_id` + `items_amount` 时附 `applicable` / `reason` / `discount_preview` |
| GET | `/api/customer/coupon-packages` | 货架：价格、面额、张数、剩余、`can_buy` / `reason` |
| POST | `/api/customer/coupon-packages/<id>/purchase` | 购买（模拟支付）：扣库存 → 记购买 → 批量发券 |
| POST | `/api/customer/orders` | body 增加 `user_coupon_id`；金额由服务端唯一计价函数计算 |

## 七、界面

- **首页**：`Coupons` 入口（账户页 Shortcuts）
- **我的券** `/customer/coupons`：三个分组 + 去券包货架的入口
- **券包货架** `/customer/coupons/store`：档位卡片、购买确认、购买后跳回我的券
- **结算页**：汇总里多一行 `Coupon`，点开底部弹层选券；不可用的券会写清原因
- **订单详情**：已有 `Discount −¥x` 行

## 八、验收点（已进 smoke_test）

购买发券 · 钱包增加对应张数 · 券可用于该店 · 抵扣与实付一致 · 同一张券不能用两次 ·
取消退券且可再用 · 限购生效 · 别人的券 404 · 过期券 409 · 百分比券封顶生效。

## 九、有意不做的

- **膨胀 / 会员卡 / 免费日领**：玩法复杂度高，不增加系统完整性；
- **真实支付与结算**：支付是模拟的，平台/商家的分账只体现在订单金额上，不建结算表；
- **券包退款**：虚拟商品，页面已明示不退。
