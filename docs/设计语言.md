## 〇、结论先行

**三个端各做一套设计，不追求跨端视觉统一。**

| | 顾客端 | 商家端 | 骑手端 |
|---|---|---|---|
| 面向 | 手机，素人，看图下单 | 桌面，店家，盯单改菜 | 手机，户外单手，抢单跑单 |
| 气质 | 消费级、轻、有食欲 | 后台工具、密集、冷静 | 工具感、动作优先、无装饰 |
| 一句话 | 白底大图红按钮 | 粉白底密集表格酒红 | 浅灰底大橙按钮 |

依据：

1. **一个用户不会同时持有三种身份。** 顾客不会看到商家后台，商家不会看到骑手台，骑手不会看到顾客的结算页。跨端视觉一致性因此不是可感知的需求。
2. **参考素材本身就是三个独立产品。** DoorDash 顾客端、Merchant Portal 商家后台、Rider Dashboard 骑手台，是三套互不相干的设计系统。我们照着做，等于照着一个已被验证的行业事实做。
3. **三方的使用场景差异太大，统一会互相拖累。** 商家端要在一屏里塞 8 列数据，顾客端一屏只做一个决策；把它们的字号、密度、圆角统一起来，必然一方吃亏。

**另外还有第四套：管理大屏（`/admin`）。** 它不是第四个角色，而是给平台运营看的只读观测面，
所以同样单独一套 token、独立的 `a-` 前缀，见本文 §十一。

**界面语言：全部英文。** 三端的 UI 文案、示例数据、错误提示一律英文，与本报告语言一致；本文档和团队内部文档仍用中文。三套样张页 `demo-{customer,merchant,rider}.html` 已按英文重写。

## 六、三端唯一必须一致的东西

**不是视觉，是语言与数据。** 这是"一个服务"的唯一证据，成本极低，必须做：

| 项 | 说明 |
|---|---|
| **状态词表** | 七种订单状态在三端用**完全相同的英文词**，见 6.1。不许顾客端写 `In the kitchen`、商家端写 `Preparing` |
| **产品名** | `xLLM` 出现在三端登录页与页脚 |
| **文案语气** | 英文、第二人称 `you`、句子短、句首大写（sentence case）；错误提示必须给下一步动作，而不只是报错 |
| **时间与金额格式** | 时间 `HH:mm`；金额 `¥12.00` 两位小数；距离 `1.2 km`；热量 `640 kcal` |
| **焦点环** | 三端都必须可见（`reset.css` 已统一 `:focus-visible`） |
| **数字等宽** | 三端都用 `.num` |
| **API 契约** | 同一个 `docs/API契约.md`，三端共用一套接口与错误码 |

### 6.1 状态标签权威词表

**这是三端唯一的语言契约，改动需三人一致同意。** `orders.status` 落库是英文枚举，UI 标签也用英文，且三端一字不差：

| `orders.status` | UI label | 顾客端 | 商家端 | 骑手端 |
|---|---|---|---|---|
| `pending` | **Placed** | 时间轴节点 | 队列列 | — |
| `accepted` | **Accepted** | 时间轴节点 | 队列列 | — |
| `preparing` | **Preparing** | 时间轴节点 | 队列列 | — |
| `ready` | **Ready** | 不单独显示（并入 On the way 之前的状态） | 队列列 | 可接单池标签 |
| `delivering` | **On the way** | 时间轴节点 | 队列列 | 进行中标签 |
| `delivered` | **Delivered** | 时间轴节点 | 已完成 | 完成反馈 |
| `cancelled` | **Cancelled** | 红色横幅（不进时间轴） | 异常列表 | — |

配套动作文案（按钮）也统一，避免同一动作三种叫法：

## 七、代码结构：把"独立"写进工程约束

```
server/
├── static/css/reset.css        三端唯一共享文件（纯技术：reset + 焦点环 + .num + .sr-only）
│
├── customer/                   ── A ──
│   ├── routes.py               页面 /customer/... + 接口 /api/customer/...
│   ├── templates/customer/design-system.html
│   └── static/css/customer.css 顾客端整套（token + 组件）
│
├── merchant/                   ── B ──（结构同 customer/）
│   ├── routes.py
│   ├── templates/merchant/design-system.html
│   └── static/css/merchant.css
│
└── rider/                      ── C ──（结构同 customer/）
    ├── routes.py
    ├── templates/rider/design-system.html
    └── static/css/rider.css
```

> ⚠️ 模板必须放在 `templates/<角色>/` 子目录里。Flask 的 Jinja 加载器会把所有蓝图的
> `templates/` 加进同一个搜索路径，三个蓝图都用 `design-system.html` 这个名字时，
> **先被找到的那个会覆盖另外两个**（实测过：三端渲染出完全相同的 HTML）。加一层角色目录即可根治。

**三条硬规则**：

1. **类名前缀不可混用**：`c-` / `m-` / `r-`。物理上写不出"用顾客端按钮的商家页面"。
2. **每个端只引 `reset.css` + 自己那一个 css**，不允许第三端引用别端的文件。
3. **各端 css 是自包含的**：token 直接写在该文件顶部的 `:root` 里，**没有**共享 tokens 文件——共享一套 token 就等于把三端绑在一起了。

好处同时也是分工边界：**A 独占 `customer.css`，B 独占 `merchant.css`，C 独占 `rider.css`**，互相不会改到对方的文件，git 冲突概率接近零。

## 八、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **评分观感** | 三个界面毫无关联，可能被读成"三个 App 拼起来"，而题目要求"一个服务连接三方" | ① 第三十节的文案与状态词统一；② 答辩时主动说明：真实平台（DoorDash / Uber Eats）的顾客端、商家端、骑手端就是三套独立设计，我们遵循同一行业惯例；③ 三端登录页都出现 `xLLM` |
| **工作量** | 三套组件，看起来是三倍 | 结构可复制（组件清单相同，只是规格不同），实际增量约 40%；且三人并行，不共享文件反而更快 |
| **维护** | 改一个通用问题要改三处 | 只有 `reset.css` 共享，改一次即可；设计规格差异本来就不该被"统一"批量修改 |
| **M1 报告不一致** | §6.4 原文已改 | 见第一节；若已提交需口头更正 |

## 十一、第四套：管理大屏（运营视角）

> 实现见 `server/admin/static/css/admin.css`，独立说明见 [`管理大屏.md`](管理大屏.md)。

大屏不是"第四个角色"，而是给运营看的观测面。它同样走"一套界面一套 token"：

| | 管理大屏 |
|---|---|
| **页面底色** | `#05080F`（近黑，叠加两团极淡的青/蓝径向光 + 44px 网格底纹） |
| **面板底色** | `#0B1220` / `#0E1828` |
| **描边** | `#182236` 1px（**唯一的层级手段，全站零阴影**） |
| **技术主色** | `#3FE3BE` 青绿（LIVE、主按钮、订单柱状） |
| **辅助色** | `#5B9BFF` 蓝（营收折线）、`#FFC24B` 琥珀（等待/延迟）、`#FF5D6C` 红（取消/超时）、`#A98BFF` 紫（备餐中） |
| **圆角** | **3px**（比商家端更方，接近仪表盘读数区） |
| **字体** | 系统无衬线 + **等宽数字**（`tabular-nums`，数字刷新时不抖动） |
| **字号** | 10 / 11 / 12 / 13 + KPI 30px + 时钟 17px |
| **密度** | 极高：1080p 一屏放 6 个 KPI + 4 张图 + 3 张表 + 一条流水 |
| **类名前缀** | `a-` |

三条取值理由：

1. **底色必须暗。** 这块墙是长时间挂着的，白底在暗环境里刺眼；深色还能让青绿信号色跳出来，
   异常和 LIVE 状态隔几米就能看到。
2. **用等宽数字。** 每 10 秒刷新一次，比例字体下数字宽度会变，整行跟着抖；`tabular-nums`
   让 "12 → 8" 这种刷新不产生位移。
3. **零阴影 + 3px 方角。** 三端里只有顾客端用投影表达"可点击的卡片"；大屏要让 30 个数字同时
   可比，任何装饰性阴影都会变成噪声。

与三端的关系：**只共享 `reset.css` 和状态词表**（Placed / Accepted / Preparing / Ready /
On the way / Delivered / Cancelled 一字不差），颜色、圆角、字体、组件全部独立。
