## 二、三端接口前缀

每个端在 `routes.py` 里定义**一对**蓝图（页面 + 接口），前缀固定：

| 端 | 页面前缀 | 接口前缀 | 静态资源 |
|---|---|---|---|
| 顾客端 | `/customer/...` | `/api/customer/...` | `/customer/static/...` |
| 商家端 | `/merchant/...` | `/api/merchant/...` | `/merchant/static/...` |
| 骑手端 | `/rider/...` | `/api/rider/...` | `/rider/static/...` |
| 官网 | `/info/...` | — | `/info/static/...` |
| 管理大屏 | `/admin/...` | `/api/admin/...` | `/admin/static/...` |
| 公共 | — | `/api/auth/...` · `/api/ping` | `/static/...` |

根路径 `/` 不渲染任何东西：302 到 `/info/`。官网是门面，三端从它的演示入口进。

```python
# customer/routes.py
pages = Blueprint("customer", __name__, url_prefix="/customer",
                  template_folder="templates", static_folder="static",
                  static_url_path="/static")
api   = Blueprint("customer_api", __name__, url_prefix="/api/customer")
```

**为什么接口按角色划分，而不是 `/api/orders` 这种按实体划分**：
订单会被三方都碰。按实体划分时，三个人的代码会挤进同一个 `orders.py`，
互相踩改动、也说不清一行代码归谁。按角色划分后，A 的文件里只可能出现顾客的动作。

## 三、四个"不能复制"的东西

以下四样必须只有**一份**。复制成三份 = 同一份订单有三套写法，数据必然打架：

| 东西 | 在哪 | 为什么不能复制 |
|---|---|---|
| `models.py` | `shared/` | 同一张表的 ORM 定义有两份，字段迟早对不上 |
| 订单状态机 | `shared/order_flow.py` | 三端各判一遍 `if status == ...`，漏一处就是越权改状态 |
| `@require_role` | `shared/security.py` | 权限校验有第二份实现，等于有一个端可以被绕过 |
| `reset.css` | `static/css/` | 三份 reset 会互相打架，且修一个 bug 要改三次 |

## 四、本地运行

```bash
cd server
pip install -r requirements.txt
python app.py
```

本地没有 MySQL 时，用 SQLite 跑同一套代码（`DATABASE_URL` 是给开发用的逃生口）：

```bash
cd server
DATABASE_URL=sqlite:///$(pwd)/dev.db ../.venv/bin/python -m shared.seed --reset
DATABASE_URL=sqlite:///$(pwd)/dev.db python app.py
```

| 地址 | 用途 |
|---|---|
| http://127.0.0.1:8080/customer/ | 顾客端首页（未登录会跳登录页） |
| http://127.0.0.1:8080/merchant/ | 商家端总览 |
| http://127.0.0.1:8080/rider/ | 骑手端工作台 |
| http://127.0.0.1:8080/customer/design-system | 顾客端设计规范样张 |
| http://127.0.0.1:8080/merchant/design-system | 商家端设计规范样张 |
| http://127.0.0.1:8080/rider/design-system | 骑手端设计规范样张 |
| http://127.0.0.1:8080/api/ping | 连通性自检 |
| http://127.0.0.1:8080/api/customer/ping | 顾客端链路自检 |
| http://127.0.0.1:8080/api/merchant/ping | 商家端链路自检 |
| http://127.0.0.1:8080/api/rider/ping | 骑手端链路自检 |

> ⚠️ 三端的样张页现在是 **Jinja2 模板**（要用 `url_for` 生成静态资源地址），
> 必须经 Flask 访问，**不能双击用浏览器打开文件**。

## 五、答辩时的讲解顺序（每人 3 分钟）

1. **打开自己的目录**，说清三件事：`routes.py` / `templates/` / `static/css/` 各是什么
2. **展示自己那套设计系统**（`/xxx/design-system`），讲一句"为什么这一端长这样"
   —— 三端的视觉语言是故意不同的，见 `docs/设计语言.md`
3. **走一条完整链路**：页面 → 接口 → 数据表。例如骑手：
   `rider/templates/` 的可接单池 → `GET /api/rider/pool` → `orders` 表 `status='ready'` 且 `rider_id IS NULL`
4. **指出共享的部分**：`shared/models.py` 与订单状态机是三个人共用的，
   说清"我的端怎么调用它、它为什么不能各写一份"
