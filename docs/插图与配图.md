# 插图与配图 · 怎么出、怎么接、怎么换

> 一句话：**菜品和店铺的照片全部是 AI 生成的实拍风格图**，没有一张来自第三方素材库。
> 事实来源是 [`art-spec.json`](art-spec.json)，出图脚本是 [`../tools/gen-art.mjs`](../tools/gen-art.mjs)。

---

## 一、为什么是实拍

最早做过一版**扁平矢量插画**（三点色、粗轮廓），出来像"设计素材包"——参数都对，
但不像一家真的在接单的店。换成实拍之后，界面第一眼就从"课程 demo"变成了"这是个外卖平台"。

决定下来的四条：

1. **全英文语境。** 界面是英文的，菜名是英文的，图里就不能出现中式店铺招牌。
2. **不出现真人正脸。** 火山方舟的内容安全闸会拒写实人脸
   （`InputImageSensitiveContentDetected.PrivacyInformation`）。所以人物一律背影、
   侧后方、戴头盔，或者只出现手——这恰好也是真实外卖 App 的取景方式。
3. **不出现任何文字、招牌、菜单、价签、logo。** 模型写中文必糊、写英文必错，
   而且这是实拍最容易翻车的地方，构图要主动避开。
4. **灯光统一：暖钨丝主光 + 冷调窗光补光。** 这是"正在营业的餐厅"的光，
   不是摄影棚白光。摆盘允许有一点点不完美（歪、碎屑、油光），整齐就变素材照了。

## 三、怎么出图

```bash
node tools/gen-art.mjs --dry-run                     # 只打印提示词，不花钱
node tools/gen-art.mjs --list-models                 # 账户里有哪些模型（免费）
node tools/gen-art.mjs --only dish-mapo              # 出一条
node tools/gen-art.mjs --prefix dish- --ref cover-sakura --skip-existing   # 出一组
node tools/gen-art.mjs                               # 全部（已存在的会重出）
```

| 参数 | 作用 |
|---|---|
| `--dry-run` | 不发请求，确认提示词和尺寸 |
| `--list-models` | 免费；**别照抄文档里的型号**，账户里能调的才是真的 |
| `--only <id>` | 单条 |
| `--prefix <前缀>` | 按 id 前缀过滤（`dish-` / `cover-` / `login-`） |
| `--ref <参考图>` | 出某个分组：`--ref cover-sakura` = 日料那一批 |
| `--skip-existing` | 已经出过的跳过，重跑不重复花钱 |
| `--n <k>` | 每条出 k 张候选（**接口一次只出一张，要几张调几次**） |
| `--out <目录>` | 丢到临时目录试，不覆盖正式文件 |

**key 不在仓库里。** 脚本先读 `process.env.ARK_API_KEY`，读不到就去
`~/dev/aiagent/.env` 借（那是火山方舟的 key，北京区，**别换区**——
一个区域一个域名，key 绑在区域上，换域名会报成 key 失效）。

## 四、40 张图怎么保证像同一家店

靠**参考图**，不靠提示词。`art-spec.json` 里 `_refs` 登记了定调图，
每条 `refs` 引用它：

```json
"refs": ["cover-goldenwok"]
```

脚本把参考图转成 dataURL 一起发（`image: [...]`），餐具、桌面、灯光、色温就锁住了。
同一家店的四道菜，出图时会带上该店封面；四家店各有一套封面当锚点。

**少了参考图不报错，只会"出的图不像"** —— 那是最费钱的失败方式。
所以脚本里找不到参考图就直接跳过这一条，不硬发。

## 五、接进界面：缺图必须有兜底

数据库里 `menu_items.image_url` 和 `restaurants.cover_url` 存的是
`/static/img/food/xxx.jpg` 这样的路径。**这两列一直存在**（M1 建表时就有），
只是以前没填。

三端渲染统一走一个 `photoOrEmoji()`：

```js
// 有图 → <img>；没图 → emoji
'<span class="c-em">🥟</span>' + '<img class="c-photo" src="…" onerror="this.remove()">'
```

emoji 永远垫在图**下面**，图 404 时 `onerror` 把 `<img>` 摘掉，emoji 就露出来——
不会出现浏览器那种碎图图标。**新加的菜、被删掉的菜、没参与出图的菜，都还能正常显示。**

线上补图（不重灌种子，不会清订单）：

```bash
cd server && set -a && . ../.env && set +a && ../.venv/bin/python ../tools/backfill-images.py
```

## 六、踩过的坑（都别再踩）

| 现象 | 原因 | 解法 |
|---|---|---|
| `HTTP 400: image area must be at least 921600 pixels` | 尺寸太小 | 4:3 至少 1152×864；1280×720 是下限 |
| 一个进程**卡十分钟不动** | `fetch` 没有超时 | 脚本已经给到 180 秒，超时算这条失败 |
| 封面图永远显示**左上角** | `.c-hero { background: … }` 简写把 `background-size/position` 重置了 | 基础规则写 `background-image`，JS 里连 size/position 一起写行内 |
| 三个封面被重复覆盖 | `--ref cover-goldenwok` 同时匹配了**引用它的三张封面** | 加 `--prefix dish-` 限定 |
| 并行跑两批，两边都慢 | 同一账号的请求会排队 | **一次只跑一个出图进程** |
