# 功能核对表 · FR / NFR 逐条对照

> 用途：**答辩时对着这张表回答"哪条需求在哪里实现"**。
> 自动化验证见 [`tools/smoke_test.py`](../tools/smoke_test.py)（132 项，SQLite 与 MySQL 8.4 均通过）。

```bash
cd server
DATABASE_URL="sqlite:////tmp/xllm-smoke.db" ../.venv/bin/python ../tools/smoke_test.py
```

测试最后一段 `=== subdomain routing ===` 直接改 `app.config` 打开三个域名，
用测试客户端的 `Host` 头模拟浏览器，**不需要 DNS、不需要 nginx** 就能验域名分流：

| 用例 | 期望 |
|---|---|
| 角色域名 `/` | 302 到本端首页（`/customer/` 等） |
| 角色域名下访问别的端的页面 | 302 到那个端的域名 |
| 角色域名下访问 `/info/`、`/admin/` | 302 回主域名 |
| 角色域名下访问 `/api/...` | **不跳转**，正常响应 |
| 域名配置全部清空 | 退回原来的行为（根路径回 `/info/`） |

## 一、功能需求 FR

| # | 需求 | 实现位置 | 验证方式 |
|---|---|---|---|
| FR-1 | 三端共用一个注册/登录入口 | `shared/auth.py`；页面 `/customer/login`、`/merchant/login`、`/rider/login` | 三种角色注册后 `role` 决定落地哪一端 |
| FR-2 | 只能读写自己所属的数据 | 每条查询带归属条件（`customer_id` / `restaurant_id` / `rider_id`） | 越权用例：顾客读别人订单、商家读别家订单、骑手动别人的单，全部拒绝 |
| FR-3 | 改数据的权限在**服务端**判断 | `@require_role`（接口）+ `@role_page`（页面）+ 归属查询 | 前端隐藏按钮不算；直接 curl 越权接口返回 401/403/404 |
| FR-4 | 商家看不到别家的单、菜单、营收 | `_my_restaurant()` / `_my_order()` / `menu-items` 全部按 `owner_id` 过滤 | 「other merchant cannot read the order / edit the dish」用例 |
| FR-5 | 菜品增删改查 | `POST/PATCH/DELETE /api/merchant/menu-items[/<id>]` + `merchant/menu` | 冒烟测试建菜、改价、下架、删除 |
| FR-6 | 售罄与剩余份数 | `stock` + `is_available`；顾客端 `sold_out` 由后端算 | 「sold-out dish is rejected」「stock decreased」 |
| FR-7 | 每天营业时间、整天休息 | `opening_hours` 表 + `PUT /api/merchant/settings` | 「opening hours saved」「paused store rejects orders」 |
| FR-8 | 商家设置订单的备餐状态 | `accepted → preparing → ready` 三个动作 | 状态机用例全链路 |
| FR-9 | 顾客浏览餐厅与菜单 | `GET /api/customer/restaurants[/<id>]` | 「restaurant list returns 4 stores」「grouped menu」 |
| FR-10 | 地图选点生成收货地址 | `/customer/addresses` + 高德 JS API（无 Key 时降级文本地址） | 手动验证；`AMAP_JS_KEY` 未配置时页面给出说明 |
| FR-11 | 超出配送半径拒绝下单 | `haversine_km` + `delivery_radius_km`，下单与改地址两处校验 | 「minimum order / paused store / out-of-radius」用例 |
| FR-12 | 一单多菜、带数量 | `orders` + `order_items`，数量合并后校验库存 | 下单用例含两种菜各 2 份 |
| FR-13 | 地址/菜名/单价快照 | `orders.delivery_*`、`order_items.name_snapshot/unit_price` | 商家改价后历史订单金额不变（快照字段） |
| FR-14 | 顾客查看自己订单的进度 | `GET /api/customer/orders/<id>` 的 `steps[]` + `order_timeline()` | 「all timeline steps are done」 |
| FR-15 | 显式状态机 | `shared/order_flow.py::TRANSITIONS / transition()` | 非法流转返回 409，重复接单被拒 |
| FR-16 | 只有该角色能执行对应流转 | `transition(order, target, actor)` 校验 actor | 「customer cannot accept an order」 |
| FR-17 | 分阶段取消 | pending/accepted 顾客可取消；preparing 之后拒绝并提示联系餐厅 | 「customer cancels a pending order」「cannot cancel while preparing」 |
| FR-18 | 商家标记延迟，顾客可见 | `POST /api/merchant/orders/<id>/delay` → `delay_flagged_at` + 预计时间 +10 分钟；顾客端 `is_delayed` 横幅 | 「merchant flags a delay」「customer sees the delay」 |
| FR-19 | 取餐前可改配送地址，骑手可见 | `POST /api/customer/orders/<id>/address`，重算距离/预计时间，写 `address_updated_at`；骑手端横幅 | 「customer changes the delivery address」「address cannot change after pickup」 |
| FR-20 | 骑手看到已备好且无人认领的单 | `GET /api/rider/pool`：`status=ready AND rider_id IS NULL` | 「order appears in the pool」 |
| FR-21 | 抢单原子性 | 一条 `UPDATE ... WHERE rider_id IS NULL` + `rowcount` | 「second rider cannot claim it (atomic)」 |
| FR-22 | 取餐、送达两个动作 | `POST .../pickup`、`POST .../deliver` | 全链路用例 |
| FR-23 | 骑手上报位置，顾客可见 | `POST .../location`（精度/速度校验）+ 顾客订单页 `rider_location` | 「rider reports a location」「weak GPS / impossible jump rejected」 |
| FR-24 | 1–5 星评价商家与骑手 + 评论 | `POST /api/customer/orders/<id>/review` → `reviews` | 「customer reviews the order」 |
| FR-25 | 只有下单顾客能评，每方一次 | `order_id` 归属 + `UNIQUE(order_id, target_type)` | 「second review is rejected」 |
| FR-26 | 优惠券 | **未实现**：表已建（`coupons` / `user_coupons`），仅作为后续扩展 | 报告与 README 均已声明"非题目要求" |

> FR-26 是有意不做的：M1 §2 已明确它**不是题目要求**，且会挤占交付时间。
> ER 图与表结构保留，答辩时作为"如果继续做会从哪里接"的回答。

## 二、非功能需求 NFR

| # | 需求 | 实现 | 状态 |
|---|---|---|---|
| NFR-1 | 全站 HTTPS | nginx + TrustAsia 证书（`xllm.cloud`），HTTP 301 跳转 | ✅ |
| NFR-2 | 密码只存加盐哈希 | werkzeug `scrypt`，`to_dict()` 永不带 `password_hash` | ✅ |
| NFR-3 | 每个接口服务端鉴权 | `@require_role` + 归属条件；`tools/smoke_test.py` 有越权用例 | ✅ |
| NFR-4 | 手机可用 | 顾客端 / 骑手端 480–520px 单列布局；商家端 1280+ 也可横向滚动 | ✅ |
| NFR-5 | 越权访问要留痕 | `security.log_denied()` 写 `[denied] uid=… role=… path=… reason=…` 到 gunicorn 日志 | ✅ |
| NFR-6 | 地图不可用时优雅降级 | 未配置 `AMAP_JS_KEY` 时地址页显示说明并用城市中心坐标；距离校验在**后端**算，不依赖地图 | ✅ |

查看拒绝日志：

```bash
ssh xllm 'sudo journalctl -u xllm -n 200 | grep denied'
```

## 三、题目原文逐句对照

| 题目原文 | 对应实现 |
|---|---|
| connects customers, several restaurants and delivery staff | 三种角色 + 4 家种子餐厅 + 3 名骑手 |
| Each restaurant controls its own opening times, menu and preparation capacity | FR-5/6/7 + `max_concurrent_orders`（满产能时顾客端显示 Busy） |
| this information may change during the day | 营业开关、单日休息、售罄、库存都会实时影响顾客端 |
| the restaurant and a delivery member need to coordinate preparation and collection | 状态机 `ready` 状态 + 骑手可接单池 |
| the customer expects useful information about progress | 时间轴 + 预计送达 + 延迟横幅 + 骑手最后上报位置 |
| Delays, unavailable dishes, address problems or cancellations can interrupt | FR-6 售罄 / FR-11 地址越界 / FR-17 取消 / FR-18 延迟 / 商家异常页 `issues` |
| without giving everyone access to the same information | 归属查询 + 角色装饰器 + 越权日志 + 三端各自的信息裁剪 |

## 四、明确不做（与 M1 一致）

| 项 | 原因 |
|---|---|
| 真实支付 | 模拟支付：下单即 `paid`，取消即 `refunded`；不接网关 |
| 真实短信 / 推送 | 界面状态与"已通知"文案是模拟的 |
| 第三方登录（Google/Apple） | 需 OAuth 配置，brief §4 申报成本高于收益 |
| 与骑手聊天 | 题目未要求 |
| 商家入驻审核 / 平台后台 | `项目规划.md` §2 已排除 |
| 优惠券 | 题目未要求，FR-26 |
