# 前端实现约定 · 三端通用

> 这是三个端写前端时**必须遵守的那一份约定**。
> 设计规格看 [`设计语言.md`](设计语言.md)，页面素材对照看 [`reference/ui/素材清单.md`](reference/ui/素材清单.md)，
> 接口的权威定义永远是各端的 `server/<角色>/routes.py`。

---

## 一、文件边界

| 端 | 你能改的 | 绝对不能改 |
|---|---|---|
| 顾客端 A | `server/customer/templates/customer/**`、`server/customer/static/css/customer.css`、`server/customer/static/js/customer.js` | `routes.py`、`shared/**`、另两端的任何文件 |
| 商家端 B | `server/merchant/templates/merchant/**`、`server/merchant/static/css/merchant.css`、`server/merchant/static/js/merchant.js` | 同上 |
| 骑手端 C | `server/rider/templates/rider/**`、`server/rider/static/css/rider.css`、`server/rider/static/js/rider.js` | 同上 |

三端**只共享 `server/static/css/reset.css`**（纯技术层）。每端的 css 自包含、类名前缀不同
（`c-` / `m-` / `r-`），不引用别端的类、变量、图片。

模板放在 `templates/<角色>/` 子目录，渲染名是 `"<角色>/xxx.html"`。**缺模板 = 页面 500**，
所以 route 里 `render_template` 提到的每个文件都必须存在。

### 跨端的链接怎么写

三个端各有一个子域名（`customer` / `restaurant` / `delivery.xllm.cloud`）。**链到自己端用相对路径**
（`/customer/orders`），**链到别的端一律用 `portal_url()`**，不要手写 `/merchant/login`：

```jinja
<a href="{{ portal_url('merchant', 'login') }}">Merchant portal →</a>
```

- 线上渲染成 `https://restaurant.xllm.cloud/merchant/login`，一步到位、不经过一次 302；
- 本地（没配域名）渲染成 `/merchant/login`，照样点得通。

站内链接写成相对路径**也不会错**：`shared/hosts.py` 会把跨端的页面请求 302 到对应域名，
只是多一跳。别写成 `https://xllm.cloud/merchant/login` 这种绝对地址 —— 本地开发就死了。

## 二、技术约束

1. **Jinja2 + 原生 JavaScript（fetch）**。不引入任何 CDN：没有 jQuery、Bootstrap、Tailwind、
   Google Fonts、图表库、图标库。图标一律内联 SVG。图表用 CSS 画（宽度百分比条形图即可）。
2. **没有图片资产**。菜品/店铺的视觉全部用「渐变底 + emoji」：
   接口已经返回 `emoji` 字段（`shared/catalog.py` 生成），前端按分类或 id 生成稳定的渐变色。
   不允许引用 `docs/reference/` 里的截图，也不允许外链图片。
3. 每个页面都要有：**加载态**、**错误态**（把后端 `error` 文案显示出来）、**空状态**。
4. 表单必须有 `<label>`（视觉上可用 `.sr-only`），键盘可操作，`:focus-visible` 不被抹掉。
5. 金额 `¥12.00`（两位小数）、时间 `HH:mm`、日期 `Oct 22`、距离 `1.2 km`、热量 `640 kcal`。
6. **界面语言全英文**，sentence case，第二人称 `you`。代码注释可以中文。
7. 不要写死演示数据在前端：一律从接口取。

## 三、接口约定

统一响应：

```json
{ "ok": true,  "data": { ... } }
{ "ok": false, "error": "Human readable reason with a next step" }
```

`fetch` 封装建议（放进各端自己的 js 里，不要共享）：

```js
async function api(path, options = {}) {
  const res = await fetch(path, {
    headers: { 'Content-Type': 'application/json' },
    credentials: 'same-origin',
    ...options,
  });
  const json = await res.json().catch(() => ({ ok: false, error: 'Network error' }));
  if (res.status === 401) { location.href = '/<role>/login'; throw new Error('401'); }
  if (!json.ok) throw new Error(json.error || 'Request failed');
  return json.data;
}
```

### 认证（三端共用）

| 方法 | 路径 | 载荷 |
|---|---|---|
| POST | `/api/auth/login` | `{account, password}` → `{user}` |
| POST | `/api/auth/register` | `{username, email, password, role, phone}` → `{user}` |
| POST | `/api/auth/code/send` | `{email, purpose: "login"\|"reset_password"}` |
| POST | `/api/auth/code/login` | `{email, code}` |
| POST | `/api/auth/password/reset` | `{email, code, new_password}` |
| POST | `/api/auth/logout` | — |
| GET | `/api/auth/me` | — |

- `role` 分别是 `customer` / `restaurant` / `rider`。注册成功即登录。
- 登录/注册成功后跳转：顾客 `/customer/`、商家 `/merchant/`（没有店铺会自动跳到 `/merchant/setup`）、骑手 `/rider/`。
- 三端登录页都出现产品名 `xLLM`，侧链另外两个端（`Merchant portal →` / `Rider portal →`）。
- 顾客注册页含"用邮箱验证码登录"和"忘记密码"，用上面的 code 接口实现；**不做第三方登录**。

## 六、各端不能丢的特征

| | 顾客端 | 商家端 | 骑手端 |
|---|---|---|---|
| 底色 | `#FFFFFF` | `#FBF5F7` | `#F4F5F4` |
| 主色 | `#EB1700` 红 | `#B11955` 酒红 | `#D08A38` 橙 |
| 主按钮 | 48px **胶囊** | 32px 方角 6px | **56px** 方角 10px |
| 投影 | **有**（唯一有投影的一端） | 无，1px 描边 | 无，1px 描边 |
| 字号 | 14px | 13px | **15px**（三端最大） |
| 导航 | 底部 Tab 52px | 顶栏 + 分段 Tab | 顶部分段 Tab |

六条硬规则：

1. 不混用类名前缀；不 import 别端 css。
2. 不用投影的端就不要偷偷加 `box-shadow`（除了商家端开关滑块那种 1px 小阴影）。
3. 骑手端按钮必须够大（主按钮 56px）、次要文字用 `#5A5A5A` 而不是浅灰。
4. 顾客端一屏一个决策，列表留白；商家端要密，表格行高 56px。
5. 三端状态标签、动作文案照第三节表格，一字不差。
6. 焦点环可见；所有 icon-only 按钮加 `aria-label`。
